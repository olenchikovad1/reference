# Действия: группы и значки

Правило владельца (10.10.2026): на карточках и в списках рядом стоят галочка,
карандаш и корзина — как будто без разницы, что делать с объектом, и случайное
нажатие на соседнюю кнопку удаляет нужное. А рядом текстовые «Удалить» и
«Изменить» занимают место двух значков, понятных без чтения.

Сверено с GitLab Pajamas, Polaris, PatternFly, Carbon; разбор — в заметке
плана 123.

## Действия делятся на группы по смыслу

Три группы:

- **подтверждающие** — двигают работу вперёд: принять, согласовать,
  сохранить, отправить;
- **нейтральные** — ничего не портят: изменить, копировать, раскрыть,
  скачать, отменить;
- **разрушительные** — убирают или ломают: удалить, в корзину, отозвать,
  сбросить.

Группы **разделены пространством** — отступом между группами, а не внутри
(см. [composition.md](composition.md)). **Подтверждение никогда не стоит рядом
с удалением:** между ними всегда либо нейтральная группа, либо воздух. Промах
на соседнюю кнопку должен стоить в худшем случае лишнего окна, а не потерянного
объекта.

Нейтральное действие, случайное нажатие на которое ничему не вредит —
изменить, копировать, раскрыть, — **может прилегать к любой группе** по
ситуации. Причина: оно открывает окно или делает обратимое, промах на него
ничего не теряет, а ставить его отдельной группой из одной кнопки — значит
плодить группы ради правила.

**Признак:** кнопка подтверждения и кнопка удаления — соседи без
промежутка — нарушение.

## Порядок групп одинаков во всём приложении

Порядок выбирается один раз на приложение и записывается в контексте проекта:
например, слева направо — подтверждающие, нейтральные, разрушительные с краю;
в диалоге — главное действие справа. Рука привыкает к месту, и человек жмёт не
читая — значит место «принять» не может переехать на соседнем экране.

Значки — на краях группы, а не вперемешку с текстовыми кнопками.

**Признак:** на двух экранах одна и та же пара действий стоит в разном
порядке — нарушение.

## Цвет кнопки — роль её группы

Роль цвета берётся из [color.md](color.md): подтверждающее — «успех» или
«основное», нейтральное — «нейтральное», разрушительное — «опасность».

Громкость — по месту. **Разрушительное ярко-красным становится только там, где
оно главное,** — в диалоге подтверждения «Удалить заказ 14-2207?». В списках и
на карточках оно значком или тихой кнопкой той же роли: двадцать залитых
красных кнопок в столбце — и вся страница краснеет, а глаз перестаёт отличать
опасное от обычного.

**Признак:** залитая кнопка роли «опасность» в строке списка — нарушение.

## Общепринятое действие — значком

Правило владельца (06.10.2026, расширено 10.10.2026). У большинства частых действий есть значок, который человек узнаёт без чтения.
Ряд текстовых кнопок «Изменить», «Удалить», «Копировать» на каждой карточке
занимает место, читается дольше значка и делает экран похожим на форму.

Перед тем как сделать кнопку с текстом, спросить: **есть ли у этого действия
общепринятый значок?**

| Действие | Значок |
|---|---|
| удалить, в корзину | корзина |
| изменить | карандаш |
| копировать, дублировать | две страницы |
| повторить, обновить | круговая стрелка |
| добавить, создать | плюс |
| закрыть, отменить | крестик |
| подтвердить, отметить | галочка |
| найти | лупа |
| фильтр | воронка |
| настройки | шестерёнка |
| скачать | стрелка вниз в лоток |
| загрузить | стрелка вверх из лотка |
| открыть снаружи, поделиться | стрелка из квадрата |
| печать | принтер |
| ещё действия | три точки |
| назад | стрелка влево |
| развернуть, свернуть | шеврон |
| перетащить | шесть точек (ручка) |

- **Один значок — один смысл во всём приложении.** Корзина не значит то
  «удалить», то «очистить фильтр»; круговая стрелка не значит то «обновить»,
  то «повторить отправку» с другим последствием.
- **Значки — из одной библиотеки** набора проекта, не нарисованные по месту и
  не из двух наборов вперемешку: разная толщина линии видна сразу.
- **У значка без подписи — подсказка с названием действия** одним-двумя
  словами и доступное имя; последствие — там же, по
  [hints.md](hints.md#значок-без-подписи-всегда-с-подсказкой).
- Текстом остаётся **главное действие формы** («Сохранить», «Записать»), где
  слово важнее скорости узнавания, и действие без общепринятого значка.

```tsx
// Неправильно: подтверждение вплотную к удалению, всё текстом, всё одного веса.
<Button>Принять</Button>
<Button>Изменить</Button>
<Button tone="danger" variant="solid">Удалить</Button>
```

```tsx
// Правильно: подтверждение отдельно, нейтральное прилегает, удаление —
// значком роли «опасность» на краю, за воздухом.
<Flow gap="between-groups">
  <Button tone="success">Принять</Button>
  <Flow gap="inside-group">
    <IconButton icon="pencil" hint="Изменить" />
    <IconButton icon="trash" tone="danger" hint="В корзину — 30 дней можно вернуть" />
  </Flow>
</Flow>
```

## Проверка

- пройти карточку или строку списка — подтверждение и удаление не соседи,
  группы разделены воздухом;
- сравнить порядок одной пары действий на двух экранах — одинаков;
- в списках нет залитых красных кнопок, громкое разрушительное — только в
  диалоге подтверждения;
- найти текстовую кнопку с действием из таблицы — нет;
- у каждого значка без подписи — подсказка; один значок нигде не значит двух
  разных действий.

## Чего не делать

- ставить подтверждение вплотную к удалению;
- менять порядок групп от экрана к экрану;
- красить разрушительное залитым красным в каждой строке;
- подписывать текстом действие, у которого есть общепринятый значок;
- брать значки из двух библиотек или давать одному значку два смысла.
