# Сеть сборки пакетов

23.10.2026: на Linux-исполнителе реестр платформы слушает порт 4873 на
loopback хоста. Docker Desktop предоставляет имя `host.docker.internal`,
обычный Docker Engine на Linux — нет. Исходная сборка падала на `npm install`
с `ENOTFOUND host.docker.internal`.

`_build-network.sh` задаёт Linux-сборкам фронтенда сеть хоста и отображение
этого имени в `127.0.0.1`. Его используют и `build.sh`, и `test.sh`.
На Windows/macOS остаётся сеть Docker Desktop. Адрес реестра по-прежнему
читается из `PLATFORM_NPM_REGISTRY` в `infra/.env`.

Одного `host-gateway` недостаточно: реестр слушает loopback, а не адрес
моста Docker. Открывать реестр наружу ради сборки не требуется. Настройка
касается только сборки образов, сеть работающего приложения не меняется.

Проверка: production-образ фронтенда и vitest в его dev-ступени на Linux.
В выводе сборки оставлены подробности npm, чтобы следующий отказ был виден.
