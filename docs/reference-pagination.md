# Постраничная витрина — контракт US-0889

Полезное действие: дизайнер открывает большой каталог и находит нужную работу
любым сочетанием прежних отборов, не загружая заранее все карточки.

## Чтение

Новый `GET /reference/api/references/page` возвращает `items`, `total`,
`next_cursor`. Порция по умолчанию — 60, допустимо 1–120. В элементах тот же
контракт CardOut и необязательные причины поиска. `work`, версии, исходники и
надписи всех карточек в страницу не включаются. Старый `GET /references`
сохраняет прежний полный ответ для существующих потребителей.

Параметры: `q`, `drop`, `audience`, `category`, `status`, `executor`, `my_turn`,
`season` (`in`, `ending`, `out`), `only_mine`, `only_drafts`, `sort` (`date`,
`own`). Отборы выполняются на сервере до ограничения порции. Нужная работа
может оказаться в первой странице поиска, хотя находится в конце каталога.
Неизвестный сезон не становится основанием молча скрыть работу.

Без поиска порядок — время последней версии по убыванию, затем уникальный
id версии по убыванию. Своя раскладка — сначала нерасставленные по той же
дате, затем места по возрастанию с детерминированным разрешением равенства.
В поиске главнее релевантность, затем дата и id версии.

Курсор содержит последний ключ сортировки и привязан к отбору и смотрящему.
Формат непрозрачен клиенту, размер ограничен. Некорректный курсор или курсор
другого запроса — 422 с кодом `invalid_cursor`. Пустая выдача — 200, пустой
`items`, `total=0`, `next_cursor=null`. Курсор не является удостоверением;
доступ проверяется независимо на каждом запросе.

Это живой список, не многозапросная транзакция: новые записи перед курсором
появляются после обновления; удалённые перестают показываться. При переходах
сохраняется порядок неизменённых карточек без offset-сдвигов и дублей.
Сохранение и изменение раскладки инвалидируют соответствующее чтение.

## Порядок и окно

`GET /references/order` с теми же отборами возвращает только номера карточек.
Этот компактный ответ нужен по действию пользователя: соседняя карточка в
окне, перестановка, отмена/повтор. Первый экран его не запрашивает. Для
изменения раскладки запрашивается весь личный порядок, чтобы сохранение
загруженной порции не удалило места остальных карточек. Существующий PUT
сохраняет полный явный порядок и собственную серверную проверку прав.

PUT принимает до 100000 уникальных номеров. Повтор того же порядка безопасен;
дубликат, неизвестный номер или превышение предела — 422, сохранённый порядок
не меняется. Проверка существования использует один PostgreSQL-массив вместо
отдельного параметра на каждый номер, чтобы не упираться в предел asyncpg.
Старый предел 1000 был дефектом совместной работы с большой витриной.

Витрина последовательно догружает страницы при прокрутке и показывает
«Загружено 60 из 5000». Смена отбора отменяет прежнее чтение и начинает новую
последовательность. В DOM остаётся ограниченное окно рядов. Изображения
догружаются для экрана, их прогресс считается по реальным load/error.

## Проверка и границы

Нужны реальные SQL-проверки большого набора в локальной тестовой БД:
ограниченная страница, все отборы, стабильность при добавлении/удалении,
собственный порядок, неверный курсор. Браузер проверяет дозагрузку, поиск
дальней карточки, возврат, выделение и раскладку через границу страницы.
Production проверяется чтением существующего набора, без искусственного
наполнения. Печать, согласование и генерация GPT этим контрактом не меняются.

Схема не меняется. Откат совместим: прежний клиент продолжает читать полный
список, а данные и версии сохраняются.

Корректировка свидетельства 02.11.2026: ранняя браузерная фикстура проверяла
перенос 5000 на подменённом PUT и пропустила серверный предел 1000. Регрессия
`test_real_http_saves_and_restores_large_order` выполняет настоящий HTTP PUT,
перенос и возврат порядка для 5000 и 33000 работ на реальном PostgreSQL.
Транзакция сервиса фиксируется в savepoint, внешняя транзакция теста
откатывается. Проверочные записи на production не выполняются.
