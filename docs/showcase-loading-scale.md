# Живое ожидание и большой каталог

До ответа списка показывается Spinner платформы с названием этапа. После
ответа — Progress с числом готовых снимков текущего экрана. Это реальные
события load/error браузера, а не таймер, изображающий проценты скачивания.
На каждом ожидающем снимке — Spinner; отказ остаётся явной ошибкой.
На «Текстах» Spinner заменяет статичное ожидание до появления таблицы.

Сетка сохраняет полную высоту и порядок, но монтирует только видимые ряды
и запас по краям. Клавиатурная навигация прокручивает и монтирует следующий
ряд перед передачей фокуса; сфокусированная карточка сохраняется в DOM.
Перестановка, фильтры и поиск используют полный список метаданных.

Проверка 5000 синтетических карточек: до изменения монтировалось 5000,
после — 29 на первом экране, 21 в конце. Промежуточный прогресс проверяется
при неодинаковой задержке сторон. Последняя карточка доступна прокруткой,
фильтром и поиском; данные на сервер не добавляются. Автоматизация —
`scripts/stand/profile_showcase_scale.cjs`.

Список API не загружает документы work и надписи каждой версии. Полная
карточка продолжает получать работу при открытии. Это проверяется реальной
тестовой БД с откатом транзакции (`test_reference_list_loading.py`).

Граница: метаданные пока приходят одним списком. Проверка DOM на 5000
карточках не является нагрузочной проверкой БД с 5000 работами. Для больших
объёмов следующая серверная история — курсорная пагинация совместно с
поиском, всеми фильтрами и пользовательским порядком. Простой limit нельзя
добавлять: он скроет старые карточки от поиска и действий над всем набором.

Схема и производственные данные не меняются; откат — предыдущая версия
штатной установкой.
