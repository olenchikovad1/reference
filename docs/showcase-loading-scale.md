# Живое ожидание и большой каталог

До ответа списка показывается Spinner платформы с названием этапа. После
ответа — Progress с числом готовых снимков текущего экрана. Это реальные
события load/error браузера, а не таймер, изображающий проценты скачивания.
На каждом ожидающем снимке — Spinner; отказ остаётся явной ошибкой.
На «Текстах» Spinner заменяет статичное ожидание до появления таблицы.

Сетка сохраняет полную высоту и порядок, но монтирует только видимые ряды
и запас по краям. Клавиатурная навигация прокручивает и монтирует следующий
ряд перед передачей фокуса; сфокусированная карточка сохраняется в DOM.
Фильтры и поиск применяются сервером ко всему каталогу до ограничения порции.
Витрина получает по 60 карточек; при прокрутке появляются следующие порции
и счётчик «Загружено 120 из 5000». Ошибка дозагрузки сохраняет уже показанное
и предлагает повторить. Перестановка получает полный список номеров только
по явному действию, чтобы не потерять позиции незагруженных карточек.

Проверка 5000 синтетических карточек: первый экран получает 60, монтирует
29 и не запрашивает полный список или полный порядок. Промежуточный прогресс
проверяется при неодинаковой задержке сторон. Проверены сбой следующей
порции и повтор, выделение и клавиатура после дозагрузки, поиск последней
карточки, перенос в конец и отмена с сохранением всех 5000 номеров.
Данные на сервер не добавляются. Автоматизация —
`scripts/stand/profile_showcase_scale.cjs`.

Список API не загружает документы work и надписи каждой версии. Полная
карточка продолжает получать работу при открытии. Это проверяется реальной
тестовой БД с откатом транзакции (`test_reference_list_loading.py`).

Постраничный SQL-путь проверен на 5000 работах в изолированной тестовой БД
с откатом, включая отсутствие `work` в списке. Контракт и границы живого
курсора — в [reference-pagination.md](reference-pagination.md).
Это функциональная проверка большого набора, а не проверка одновременной
нагрузки от множества пользователей. Production проверяется на существующих
работах; браузерный вход ядра платформы не проверяется MCP-ключом.

Схема и производственные данные не меняются; откат — предыдущая версия
штатной установкой.
