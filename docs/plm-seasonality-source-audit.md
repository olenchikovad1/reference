## Что подтверждено и чего недостаточно

Машинный контракт PLM предоставляет окно дропа. Подтверждённый профиль
товарной группы «круглый год / сезонный / остросезонный» и её собственное
окно этим контрактом не передаются. Состав полей сам по себе не доказывает
отсутствия данных во всём PLM: нужен поддержанный контракт владельца источника.

В локальной схеме Докроя `DocroiSeasonality` хранит месячные коэффициенты
МПСТАТа m01…m12 по категории, а `DocroiSeasonalityMap` связывает предмет и
пол с путями категорий. Это кривая спроса, а не подтверждённая политика
скрытия работ. Назначить порог коэффициента или длины окна самостоятельно
означало бы выдать эвристику за требуемое решение источника.

Сверены локальные `plmapi/api/machine.py`, `plmapi/schemas/directories.py`
и `docroiapi/models/docroi.py`. HEAD локальных проектов на момент чтения:
PLM `025d16d31e6b4b1862015e4ea728f0933738394a`,
Докрой `ae873d98e94aa783d1056f6161e8cf3c6bb757c0`.
Это происхождение локального чтения, не доказательство версии production;
боевой ответ отдельно получен указанным GET.

## Конкретный остаток

US-0888 не принята. Для продолжения нужны источник и машинное чтение:
ключ товарной группы, подтверждённый профиль, её окно (включая переход года),
связь с категорией/моделью и дропом, происхождение подтверждения. Поля
с неизвестным значением должны оставаться неизвестными, без молчаливого
скрытия карточек. Новый справочник в Reference не создаётся.

Функции `profileFromWeeks`/`profileFromDates` остаются прежними эвристиками;
этот аудит не объявляет их подтверждёнными профилями. В данном изменении
нет модификации рабочего фильтра, карточек, PLM или Докроя. Дорогая
реализация останавливается до появления достаточного контракта.
