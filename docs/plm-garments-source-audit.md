чтением, из API-контейнера служебным PLM-ключом. Повторяемая процедура —

Старый дефект машинных изображений больше не воспроизводится:
`01M3MH67EBXX6G3A8GVTZWBP48/preview` отвечает 200. Чтение дропов и людей
платформы также отвечает 200, личных pfb-ключей в окружении API не найдено.
Это подтверждение поведения; SHA внешнего исправления PLM неизвестен.

В каталоге 10907 цветомоделей, но краткий индекс отдаёт ненулевое `image`
только у трёх. 79 связаны с локальным изделием для работы; проверенный
пример связи — style `2027` → `B-HDY-14`. Эту связь нельзя автоматически
распространять на другие модели одежды ради доступной кнопки.

Главная картинка 0422 — `GeneratedColoredImage…`, всего 30×40. Её нельзя
считать пригодным кадром, когда рядом лежат реальные рендеры. Аудит выбирает
явный front либо подписанный «перед», не подменяя этим проверку геометрии.
Оба проверенных рендера ниже прежнего порога 800 по меньшей стороне:
растягивание не создаёт детали. Порог можно пересмотреть по различимости
модели, но нельзя молча объявить его соблюдённым.

У двух проверенных паспортов `sizes`, `size_charts`, `patterns`, `technology`
и `bom` — пустые списки, хотя агрегат `readiness` содержит full/partial/none.
Доступны бренд, категория и название размерного ряда. Агрегат готовности
не доказывает наличие содержимого документов в машинном ответе.

Из PLM уже можно брать пантоны, выпуск/недели, фабрики/бренд/категорию,
размерный ряд, изображения и агрегаты готовности. Для точной примерки ещё
нужны подтверждённые мерки, исходный размер кадра, ориентиры и поля печати
в сантиметрах. Значения 92–176 задают названия размеров, а не ширину торса.
Документы и каталог не копируются в Postgres Reference.

Следующие границы: полноценная картинка в кратком индексе или отдельный
ограниченный запрос рендеров; корректная сторона русских названий; доступные
мерки/документы и калибровка одного изделия. US-0887/0893/9533 остаются
открытыми; восстановленный HTTP 200 сам по себе их приёмку не завершает.
