# 0002. Два класса хранения: исходники в томе, кадры и производные в объектном

**Дата:** 23.09.2026
**Касается:** `infra/compose.yaml`, `api/.env.example`, домен `assets`

## Задача

Определить, где лежат файлы. Они разного рода: исходник изделия из VStitcher —
444 МБ, читается редко и офлайн; кадр состояния — 200 КБ, уходит в браузер
постоянно.

## Решено

**Два класса, и смешивать их нельзя.**

| Класс | Что | Где | Как адресуется |
|---|---|---|---|
| Исходники | `.bw` и прочие тяжёлые файлы моделей | Файловое пространство, подключённое томом только на чтение | Путь в базе |
| Кадры и производные | Состояния изделий, миниатюры, композиты | Объектное хранилище: MinIO на стенде, Yandex Object Storage на проде | Имя по хешу содержимого |

**В репозиторий не попадает ни один из них.** В git лежит только описание —
`infra/stand/fixtures/B-HDY-14.yaml` с путями, размерами и хешами.

## Почему

**Профили обращения противоположны.** Исходник читается один раз при подготовке
изделия; кадр отдаётся при каждом открытии витрины. Хранилище, хорошее для
второго, платное и медленное для первого.

**Платить за 444 МБ в объектном хранилище незачем.** Файл не раздаётся, не
кешируется CDN и не нужен браузеру никогда.

**Хеш в имени даёт вечный кеш** — но только там, где файл маленький и
раздаётся. Для исходника это лишняя работа.

## Цена, названная явно

- **Том надо чем-то наполнить.** На пустой машине `infra/stand/files/`
  отсутствует, и загрузка фикстуры обязана падать внятно — «положи файл сюда»,
  а не молчаливым `None`.
- **Два пути в коде вместо одного.** Домен `assets` знает про оба и обязан
  сделать различие явным, а не «иногда путь, иногда ключ».
- **Хеши в фикстуре придётся обновлять руками**, если файл в томе заменят.
  Это и есть цель: подмена должна быть видна, а не обнаруживаться по странному
  результату проверок.

## Рассмотрено и отклонено

**Всё в объектное хранилище.** Отклонено: платим и за хранение, и за трафик у
файла, который никто не скачивает.

**Всё в том.** Отклонено: кадры нужны браузеру, а раздавать их через сервис
значит писать свой CDN.

**Исходники в git через LFS.** Отклонено: история репозитория начинает весить
как склад моделей, а моделей будут тысячи.
