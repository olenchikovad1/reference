# 0003. Учётки лежат открытым текстом в .env — на время прототипа

**Дата:** 23.09.2026
**Касается:** `.gitignore`, `api/.env.example`, `web/.env.example`, `infra/.env.example`

## Задача

Решить, чего стоит безопасность на стадии, когда проверяется сама идея продукта.

## Решено

**Секреты хранятся открытым текстом в `.env`.** Хранилища секретов, ротации и
шифрования на стадии прототипа нет. Скорость и удобство важнее.

**Файлы `.env` разделены по адресатам** — `api/`, `web/`, `infra/` — и в
репозиторий не попадают. Рядом лежат `.env.example`, заполненные рабочими
значениями локального стенда: копирование примера и есть вся настройка.

## Почему

**Стенд локальный и наружу не смотрит.** Пароль `reference` к постгресу внутри
докер-сети не является секретом ни в каком смысле.

**Отложена работа с секретами, а не проверка прав.** Разницу надо назвать,
потому что «не заморачиваемся про безопасность» легко прочесть шире, чем
сказано. **Объявление требуемого права на каждом изменяющем маршруте остаётся
обязательным** — без него сервис не поднимется по контракту платформы (И-4), и
это не безопасность, а условие подключения.

**Пример с рабочими значениями дешевле инструкции.** Инструкция «заполните
переменные» устаревает молча, заполненный пример — нет.

## Цена, названная явно

- **Перед первым выходом наружу решение обязано быть пересмотрено.** Повод
  назван: появление стенда, доступного не с рабочей машины. Не «когда-нибудь».
- **`.env` вне git — значит, на новой машине нужен шаг копирования.** Принято
  осознанно: альтернатива — положить настоящие учётки в историю, откуда их
  потом не вынуть.

## Рассмотрено и отклонено

**Положить `.env` в git ради полного отсутствия настройки.** Отклонено: из
истории git секрет не удаляется, и решение станет необратимым ровно в тот
момент, когда появится первый настоящий ключ Yandex.

**Сразу поднять хранилище секретов.** Отклонено: инфраструктура ради
инфраструктуры до того, как есть что защищать.
