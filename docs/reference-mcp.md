# Reference через локального помощника

MCP-вход — `https://platform.toribrands.ru/reference/api/mcp`.
Инструменты проверяют права человека на сервере; скрытый инструмент нельзя
вызвать напрямую. `prints` читает тот же каталог и решения по дропу, что
страница принтов; `reference` сохраняет совместимый счётчик versions и
дополнительно отдаёт version_history и отчёт checks.

Проверки в checks — снимок расчёта браузера при сохранении, с источником
browser-geometry, размером и признаком предварительной калибровки. Это не
новый серверный расчёт и не разрешение согласования. Если старая версия
отчёт не хранила, источник unavailable и items=null; отсутствие отчёта
не означает отсутствия нарушений. В отчёт идёт текущая композиция, а не
отложенный кадр панели проверок. Оригиналы изображений инструменты не отдают.

## Локальное подключение

`scripts/stand/reference_mcp.py` — небольшой stdio-мост к существующему
HTTP-входу. Нужна только стандартная библиотека Python. Файл ключа передаётся
параметром --access-file; ключ не записывается в config.toml, аргументы,
репозиторий или отчёты. Мост перечитывает файл на каждом запросе, запрещает
перенаправления HTTP и ограничен шестью инструментами чтения. Изменяющие
инструменты недоступны даже при наличии серверного гранта. Явный параметр
`--workflow` дополнительно подключает designer_step, review_decision,
approve_final, remark, propose_for_discussion и move_to_drop. Права и роли
проверяет тот же серверный сервис, что обслуживает интерфейс; возврат,
брак и возобновление требуют причины. В истории перехода остаются человек,
имя бота, причина и результат. Перенос обновляет явный дроп семейства вместе
с цветомоделью; при отсутствии модели в ассортименте карточка не меняется,
сохранённые версии не перезаписываются.

На машине владельца подключение зарегистрировано в личном профиле Codex
как reference_readonly и reference_workflow (с явным --workflow). Конфигурация
stdio описана в [официальной документации](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).
Регистрация настройки и выполнение вызова различаются: проверка подключения
выполняется initialize → tools/list → tools/call с реальными аргументами.

Для обновления ключа заменяют Authorization в уже используемом локальном
файле доступа платформы. Следующий запрос читает новое значение. При отказе
возвращается безопасный номер HTTP без тела и заголовков ошибки. Сервису
Reference этот файл не передаётся: production продолжает работать своим
служебным удостоверением. Если профиль переехал, в настройке подключения
обновляют пути к Python, мосту и файлу доступа; ключ повторно не копируют.

Вызов tools/list сам по себе не является демонстрацией полезности: для
приёмки читают очередь реального дропа, историю карточки и принт с решением,
сопоставляя их с теми же данными API. Проверочные изменения выполняются
только локально по решению владельца03.11.2026.
