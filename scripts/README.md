# Скрипты

`testing/run.py` — хост, стандартная библиотека + Docker: исполняемый профиль
TC-ADOPT-012 (ядро/влияние/регрессии/ротация, evidence и строгий reuse).
`testing/test_policy.py` — короткие контрольные исходы без Docker;
`testing/catalog.json` и `catalog.py` — каталог рисков/групп;
`testing/runtime.py` — одноразовые API/БД/S3 и приёмка точных образов.
Команды и границы — [docs/testing.md](../docs/testing.md).

`stand/verify_testing_contract.py` — хост, стандартная библиотека:
настоящий положительный/контрольный отрицательный процесс, reuse без повтора,
отмена reuse после изменения входа и моделируемый обход без голодания.

`audit_plans.py` — хост, стандартная библиотека: индекс общих планов Reference
и проверка их коммитов в `origin/master`; автоматического закрытия нет.

Разбор и замеры данных стенда — только отсюда (CLAUDE.md, запрет 10). Нет
нужного — пишется сюда, в раздел по предмету, и строкой в эту опись.

Где запускается — в шапке каждого скрипта. Коротко: **хост** — одна
стандартная библиотека (плюс PyYAML), `py scripts/<раздел>/<скрипт>.py` из
корня репозитория; **контейнер** — нужны PIL, numpy или код сервиса,
`docker compose -f infra/compose.yaml exec -T api python -m scripts.<раздел>.<скрипт>`.
Том файлов в контейнере только на чтение: что надо записать, уходит в stdout.
